## 核心设计立场

原始设想是一个"教材生成智能体"，但存在一条不可逾越的红线：**智能体不得直接生成教材，只能辅助检索与研究**。

本方案不在生成功能上打补丁，而是把定位整体平移——从"教材内容的生产者"改造为"教材体系研究的基础设施"，并通过**五重位移**落地：

| 维度 | 原设想 | 新定位 |
|---|---|---|
| 对象 | 生成教材 | 研究教材 |
| 产物 | 成篇内容 | 证据卡片 |
| 动作 | 撰写文本 | 检索·比对·评估·推荐 |
| 主体 | AI 主笔、人审核 | 人主笔、AI 供料 |
| 权限 | 提示词自律 | 架构级锁定 |

红线由架构而非提示词保障：系统的最小输出单位是"证据原子"——必须挂载来源、限定长度、禁止拼接成篇。**因为最小输出单位在数据结构层面就不是自由文本，系统在物理上不具备写出一本教材的能力。**

## 总体架构：「双闸六层」

六层主干（L0 语料底座 → L1 价值坐标 → L2 知识图谱 → L3 助研智能体群 → L4 体系诊断 → L5 协同共同体），加前闸门（意图识别与请求转译）、后闸门（成篇度检测与输出降级）两道红线守护装置，以全过程留痕审计链为底盘。

## 七项首创点

1. 「请求转译」而非「请求拒绝」的合规交互范式
2. 「证据原子」数据契约——把红线写进数据结构
3. 「成篇度闸门」——面向教材场景的输出侧红线检测装置
4. 「四维坐标索引」——让"中国特色"成为可计算的检索算子
5. 「案例发现」取代「案例生成」——从虚构走向实证
6. 「三色灯」人机责任分配协议
7. 「红船语料层」——不可复制的地方性知识资产

## 复现构建

```bash
# 1. 生成图示（需要环境变量 CHEDANKJ_API_KEY）
python3 gen_images.py prompts.json 图示

# 2. 生成 Word（需要 node + docx）
npm install docx
node build_docx.js 输出.docx
```

`build_docx.js` 从 `方案正文.md` 解析标题、表格、列表、引用、代码块与图片，生成带封面、静态目录（含点导线与页码）、页眉页码的 Word 文档。目录页码由两遍构建确定：第一遍渲染 PDF 定位各级标题所在页，写入 `pages.json`；第二遍据此填入页码（目录行数不变，故分页不漂移）。
