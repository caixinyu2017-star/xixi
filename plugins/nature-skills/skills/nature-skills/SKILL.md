# nature-skills — 数据分析与实证分析总入口

## 定位

用户任何与**数据分析 / 实证分析**相关的请求，都从这里进。本技能做两件事：

1. **执行分析**：按下面的 8 步流水线，用真实代码跑出真实结果。
2. **产出结果**：把结果变成论文可用的表、图、文字，路由到 nature-skills 家族里对应的专项技能。

**边界**：概念类图（示意图、机制图、路径图、技术路线图）不在这里，交给 `gpt-image-2`。
本技能只管**由数据驱动**的表和图。

---

## 8 步流水线

不是每个请求都要走满 8 步。先判断用户处在哪一步，从那一步接上；但**不能跳过第 0 步**。

### 第 0 步 — 对齐（强制，先做完再动手）

在写第一行分析代码前，把这四项写清楚并与用户确认：

| 项 | 要问清什么 |
|---|---|
| **研究问题** | 要估的因果/相关关系是什么？被解释变量、核心解释变量各是哪个？ |
| **数据** | 文件在哪、什么格式、多少行、面板还是截面、观测单位是什么、时间范围 |
| **技术栈** | Python / Stata / R？**用户没指定就问，不要默认选一个** |
| **交付物** | 只要结论？要表？要图？要能直接贴进论文的结果段落？ |

数据文件还没拿到时，不要先编一段示例代码"演示流程"——直接说明需要什么文件、什么格式。

### 第 1 步 — 数据审计

跑代码看清楚数据本身，不看数据就开始建模是最常见的错误来源。必须报告：

- 行数、列数、观测单位、面板是否平衡
- 每个将要用到的变量：缺失率、取值范围、异常值、类型是否符合预期
- 关键 ID 是否唯一、是否有重复观测
- 时间变量的覆盖区间与断档

发现问题（大面积缺失、单位不一致、明显录入错误）**先报告再处理**，处理方式要用户点头。

### 第 2 步 — 描述统计（Table 1）

按分组给出均值、标准差、极值、观测数。分组维度由研究设计决定（处理组 vs 对照组，
或按时间/地区）。格式规范见 `references/reporting-standards.md`。

### 第 3 步 — 识别策略与模型设定

写清楚：估计方程、固定效应层级、控制变量集合、标准误如何聚类、样本筛选规则。
**每一条都要说明理由**，不要只给一段代码。

用到因果识别方法时，把该方法的识别假设逐条列出，并说明打算怎么检验：

| 方法 | 必须交代的假设与检验 |
|---|---|
| DID / 双重差分 | 平行趋势（事件研究图）、处理时点是否交错、是否需要异质处理效应稳健估计量 |
| IV / 工具变量 | 相关性（第一阶段 F）、外生性（理论论证 + 可做的间接检验）、弱工具变量诊断 |
| RDD / 断点回归 | 驱动变量是否被操纵（密度检验）、带宽选择、局部多项式阶数、协变量连续性 |
| PSM / 匹配 | 共同支撑、匹配后平衡性检验、匹配算法与卡尺的敏感性 |
| 合成控制 | 供体池构造、拟合期拟合优度、安慰剂检验 |
| 面板固定效应 | 遗漏变量方向讨论、聚类层级与组数是否足够 |

### 第 4 步 — 基准估计

跑出来，报出来。逐列递进（只加核心变量 → 加控制 → 加固定效应），让读者看见系数的稳定性。
**报告的每个数字都必须来自本次实际运行的输出**。

### 第 5 步 — 稳健性检验

至少覆盖：替换被解释变量/核心变量度量、改变样本（剔除极端值、剔除特殊年份或地区）、
改变模型设定（不同固定效应、不同聚类层级）、安慰剂检验。每项说明它排除了什么替代解释。

### 第 6 步 — 机制与异质性

- **机制**：中介检验或分渠道回归，要说明为什么这条渠道在理论上成立
- **异质性**：分样本或交互项，分组维度要有事前理由，不要事后翻箱倒柜找显著

对结果显著性的解读要克制：不显著就是不显著，不要改写成"存在一定的正向趋势"。

### 第 7 步 — 表图产出

- **表**：按 `references/reporting-standards.md` 的规范出三线表
- **图**：**路由到 `nature-figure`**（Python/R 论文级绘图，含事件研究图、系数图、
  森林图、热图等）。不要用生成式图像模型画带真实数据的图。

### 第 8 步 — 结果文字与收尾

- 结果段落草稿 → **路由到 `nature-writing`**；已有草稿要润色 → **`nature-polishing`**
- 数据可得性声明、数据仓储、FAIR 元数据 → **路由到 `nature-data`**
- 需要文献支撑结论或补引用 → **路由到 `nature-citation`** / `nature-academic-search`
- 产出可复现脚本 + 结果文件清单，说明每张表/图由哪段代码生成

## 路由表

| 用户接下来要什么 | 交给谁 |
|---|---|
| 论文级图表绘制（Python/R） | `nature-figure` |
| 数据可得性声明 / 数据仓储 / FAIR | `nature-data` |
| 写结果段落、讨论、摘要 | `nature-writing` |
| 润色已有英文/中文结果段落 | `nature-polishing` |
| 补引用、找支撑文献 | `nature-citation`、`nature-academic-search` |
| 把结果做成汇报 PPT | `nature-paper2ppt` |
| 审稿意见里的计量质疑 | `nature-response` |
| 重型计量（完整 8 步计量流水线、顶刊表格模板） | `empirical-analysis-python` / `empirical-analysis-stata` / `empirical-analysis-r` / `aer-skills`（若已安装） |
| 示意图、机制图、路径图、技术路线图 | `gpt-image-2`（**不是本技能**） |

被路由到的技能不可用时（例如本技能被单独上传到 Customize、周边技能没装），
不要停下——按 `references/reporting-standards.md` 里的内置规范自己完成，
并在交付时提示用户装上对应技能可以做得更好。

## 硬性规则

1. **不编数字。** 所有系数、标准误、p 值、样本量、R²，必须来自本次真实运行的代码输出。
   没跑就说没跑。不允许出现"根据经验，该系数大约在 0.03 左右且显著"这类表述。
2. **代码可复现。** 每个结果都要能追到产生它的那段代码。交付时给出脚本文件与运行顺序。
3. **技术栈不擅自选。** 用户没说 Python/Stata/R，先问再动手。
4. **不显著就报不显著。** 不改口径凑显著，不做未声明的多重比较后只报最好的那个。
   确实做了多组检验，就说明做了几组。
5. **数据问题先报告。** 缺失、异常、口径不一致，先说清楚再决定怎么处理，处理方式让用户拍板。
6. **不用生成式图像模型画数据图。** 带真实数值的图一律走 `nature-figure`。
7. **敏感数据不外传。** 个体级数据不要贴进对话正文，只报汇总统计。
