# 禾灵儿文化德育数字画像系统

把学生在"禾灵儿"文化智能体 2.0 上留下的学习痕迹，转换成
**文化体验 / 文化认知 / 文化志趣 / 文化认同 / 文化研创** 五维雷达画像，
并随着材料不断增加动态上升——初始得分来自开课第一节课的问卷，过程由平台数据驱动。

提供三种用法：**单文件网页版（双击即用，推荐）**、可挂到"禾灵儿"网站的 Web 栏目、
以及可打包成 exe 的桌面版。**三者算分结果逐位相同。**

## 二、快速开始

### 2.0 网页版（最省事，推荐先用这个）

把 `禾灵儿德育画像.html` 存到电脑任意位置，**双击用 Edge 或 Chrome 打开**即可。

- 不需要装 Python，不需要打包，不需要联网。
- 所有计算都在你自己的浏览器里完成，数据存在浏览器本地（IndexedDB），
  **不会上传到任何服务器**。
- 换电脑或换浏览器时，用页面上的「导出数据备份」生成一个 json，
  在新机器上「导入数据备份」即可，多台机器的数据也能合并。
- 这个 html 同时也能直接放到学校网站上当静态页面用。

> 浏览器要求：Edge / Chrome 103 及以上（用到了浏览器原生的解压能力）。
> 请用普通窗口打开，不要用无痕模式，否则数据无法留存。

**网页版与下面的 Python 版算分结果逐位相同**（已用 50 名学生 × 5 维 = 250 个数值
逐一比对，最大差异 0.000e+00）。

### 2.1 打包成 exe（教师本地使用，可选）

在一台装了 **Python 3.10 ~ 3.12** 的 Windows 电脑上：

```
双击 build_exe.bat
```

约 3~6 分钟后得到 `dist\HelingrPortrait.exe`。把这个 exe 拷到任意目录双击运行即可，
数据库自动建在 exe 同目录的 `hlr_data\` 里，**不需要联网、不需要装 Python**。

> 想自定义词典或权重，把 `lexicon.json` / `weights.json` / `questionnaire_map.json`
> 放在 exe 旁边即可，程序启动时会自动读取并覆盖内置默认值。

### 2.2 部署到"禾灵儿"网站

```bash
pip install -r requirements.txt
uvicorn hlr_portrait:app --host 0.0.0.0 --port 8080
```

挂到已有的 FastAPI 工程里作为一个栏目：

```python
from fastapi import FastAPI
from hlr_portrait import app as portrait_app

main_app = FastAPI()
main_app.mount("/portrait", portrait_app)   # 访问 /portrait/ 即为画像栏目
```

数据库位置可用环境变量指定：`HLR_DB=/var/lib/helingr/portrait.db`。

### 2.3 命令行（批量导入 / 排障）

```bash
python hlr_portrait.py import 学生报名情况.xlsx --grade 大一   # 类型自动识别
python hlr_portrait.py score 2025468946310                     # 打印某生画像 JSON
python hlr_portrait.py health                                  # 数据库统计
python hlr_portrait.py serve --port 8080                       # 启动服务
python hlr_portrait.py reset-evidence                          # 清空证据后重导（调参用）
```

## 三、使用流程

1. **上传学生报名情况**——这一步建立"学号 ↔ 姓名 ↔ 昵称 ↔ 平台账号"索引，
   必须最先做，否则其余表格匹配不上学生。
2. **上传五维问卷**（问卷星导出的 xlsx）——生成每名学生的**初始得分**。
3. **上传其余三张导出表**：学生视频完成率、学生作业完成率、文化对话记录。
4. **在学生详情页补传**该生的作业成果（视频 / Word / Excel / PPT / PDF）
   与自建智能体（提示词、知识库导出文件）。
5. 列表页四列分别对应**大一 / 大二 / 大三 / 大四**，点"查看"进入详情页；
   详情页底部可**生成学习报告（Word）**与**查看成长轨迹**。

每次上传都要先选年级。同一份材料重复上传不会重复加分（见第五节）。

## 四、算分方法

### 4.1 主公式

对每个维度 *d*：

```
S_d = B_d + (1 − B_d) · (1 − e^(−A_d / κ_d))
```

- `B_d`：**初始得分**。大一由问卷换算（见 4.2）；大二及以后自动承接上一学年的
  最终得分（没有问卷、没有历史数据时取中性值 0.30）。
- `A_d`：该维度累计的**有效证据量**。
- `κ_d`：饱和常数，控制"多少材料能换多少分"，在 `weights.json` 中可调。

这个式子同时满足三条硬要求：

| 要求 | 数学保证 |
| --- | --- |
| 只做问卷时就是初始得分 | `A_d = 0 → S_d = B_d` |
| 材料越多分越高 | 对 `A_d` 严格单调递增 |
| 封顶 1.0 且永不越界 | `A_d → ∞` 时 `S_d → 1`，恒有 `S_d < 1` |

### 4.2 问卷怎么变成初始得分

问卷是**自陈量表**，只能说明"入学时的自我认知起点"，不能直接当作素养水平。
如果照搬问卷均分，学生只要每题都选最高档就一次拿满分，四年的成长再也无从体现。
因此问卷分两步换算：

**第一步：直线作答折减。** 判据是**题目级作答的标准差**——整份问卷每题都选同一档
时标准差为 0，说明作答没有任何区分度：

```
折减系数 = 0.72 + 0.28 · min(1, 题目标准差 / 0.18)
```

均分低于 0.80 时折减逐步撤销（如实报告中低分的学生不受影响）；题量不足 8 题
时无法判断，一律不折减。

**第二步：压缩到窄带。** 把折减后的"作答强度"映射到 `[0.15, 0.50]`，并用凸函数
让高分段更难触顶：

```
B_d = 0.15 + 0.35 · (作答强度_d) ^ 2.0
```

效果（每维 4 题、五点量表的推荐题本）：

| 作答方式 | 均分 | 题目 σ | 初始得分 |
| --- | --- | --- | --- |
| 每题都选"完全符合" | 1.00 | 0.000 | **0.33** |
| 几乎都选最高档，偶尔次高 | 0.99 | 0.054 | 0.37 |
| 认真作答、自评偏高 | 0.80 | 0.187 | **0.38** |
| 认真作答、自评中等 | 0.60 | 0.166 | 0.28 |
| 认真作答、自评偏低 | 0.36 | 0.167 | 0.20 |

即：**刻意刷满分反而低于认真作答的高分学生**，而问卷本身的天花板只有 0.50——
剩下的一半必须靠四年的平台使用挣。

数据库里存的是"作答强度"（0~1），换算成初始得分放在**打分时**进行，
所以日后只改 `weights.json` 的 `baseline_band` / `straight_line` 就能重算，
**不必重新导入问卷**。

> **从旧版本升级**：旧库里存的是问卷原始均分（没有过折减那一步）。升级后
> 这些数据仍能正常计算，但**建议把问卷 xlsx 重新上传一次**，让直线作答折减
> 生效。平台四张导出表、学生作业与智能体**不必重传**，权重与 κ 是在打分时
> 套用的，重新打开页面即为新分数。

### 4.3 证据量怎么来

```
A_d = Σ_渠道 min( Σ_证据 计量 × 质量 × 文化相关度 × 渠道权重 ,  渠道上限 )
```

- **计量**：课程数、视频完成数、作业提交与得分、对话有效轮次、作品体量（页数 / 时长 / 字数）。
- **质量**：完成率、得分率、文本充实度、结构完整度；"你好""继续"这类口水对话降权到 0.12。
- **文化相关度**：`0.40 ~ 1.00`。按用户要求取**稍宽松**策略——认真参与就给 0.40 保底，
  命中通用文化词 / 嘉兴地域词 / 革命文化词后逐级上浮。
- **渠道上限**：单一渠道对某维度的贡献设天花板，抑制刷量。上限作用在**汇总值**上
  （而不是按上传批次截断），因此**与上传顺序完全无关**，任何时候重算结果一致。

### 4.4 各渠道对五维的权重

权重按**单位行为的投入强度**标定。原先"报名 1 门课"的证据量约等于"8 轮有质量的
文化对话"，而报名只是一次点击——全体学生都报了课、都看了视频，分数被这两个
"参与型"渠道顶得很高，真正体现投入的对话、作业、作品反而没有分量。
现在参与型渠道压到原来的 0.35~0.40，投入型渠道抬上去（文化对话 ×3.2），
**一轮有质量的文化对话约等于报名一门课**。

| 渠道 | 类型 | 文化体验 | 文化认知 | 文化志趣 | 文化认同 | 文化研创 | 渠道上限 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 文化对话 | 投入型 | 0.640 | 1.760 | 1.600 | 1.280 | 0.800 | 10.0 |
| 文化课程报名 | 参与型 | 0.140 | 0.088 | 0.210 | 0.088 | 0.035 | 3.0 |
| 课程作业 | 投入型 | 0.350 | 0.910 | 0.560 | 0.280 | 0.490 | 8.0 |
| 课程视频 | 参与型 | 0.240 | 0.180 | 0.140 | 0.080 | 0.020 | 4.0 |
| 学生作业成果 | 投入型 | 0.473 | 0.608 | 0.405 | 0.540 | 1.148 | 12.0 |
| 学生自建智能体 | 投入型 | 0.270 | 0.675 | 0.540 | 0.473 | 1.350 | 12.0 |

饱和常数 κ 同步抬高（体验 6.5、认知 7.0、志趣 6.5、认同 5.5、研创 5.0），
让四年的持续投入拉出台阶，而不是大一一年就接近满分。

改 `weights.json` 即可调整（`channel_weights` / `kappa` / `channel_cap` /
`baseline_band` / `straight_line` / `level`），**改完刷新页面立即生效，无需重新导入**。

> 注意：词典与计量参数（`lexicon.json` 里的词表、各渠道的计量口径）会写进证据记录，
> 改动后需要 `reset-evidence` 再重新导入才会生效。

### 4.5 结果排序（材料完整度，内部机制）

列表默认**把材料最全的学生排在最前面**。理由是：材料少不代表学生差，而是
**证据不足、结论还不可靠**，教师应当先看结论最可信的那批人。

排序依据是一个内部指标"材料完整度"：

```
完整度 = 0.25·问卷初始得分 + 0.30·渠道覆盖(x/6) + 0.25·证据充分度 + 0.20·证据体量
```

> **这个指标只在后台参与排序，界面上不呈现**——不显示百分比，也不显示
> "严重不足"之类的评价标签，避免把内部机制摆到台面上误导使用者。
> 接口 `/api/students` 仍会返回 `completeness` 字段，供二次开发使用。

排序可在页面上切换为：默认、综合指数从高到低、综合指数从低到高、班级 / 学号。

### 4.6 综合指数与等级

`CCI = 五维等权算术平均`。

等级采用**随年级递增的发展性常模**——同一个分数在大一算"发展级"，到大四只能算
"起步级"，**原地不动即等于退步**，四年的成长因此在等级上也看得见：

| 年级 | A 引领级 | B 胜任级 | C 发展级 | D 起步级 |
| --- | --- | --- | --- | --- |
| 大一 | ≥ 0.60 | ≥ 0.48 | ≥ 0.36 | < 0.36 |
| 大二 | ≥ 0.68 | ≥ 0.56 | ≥ 0.44 | < 0.44 |
| 大三 | ≥ 0.76 | ≥ 0.64 | ≥ 0.52 | < 0.52 |
| 大四 | ≥ 0.84 | ≥ 0.72 | ≥ 0.60 | < 0.60 |

阈值在 `weights.json` 的 `level` 里可调（`cuts` 是大一的三条线，`step` 是每升一个
年级的抬高幅度）。

## 五、稳定性与防刷分

**"同样的内容反复上传，得分完全不变"** 是由存储层强制保证的，不是近似：

- 每条证据都带**内容指纹**。作业与智能体的指纹取**文件 SHA-256**，
  所以改文件名、换目录、重复上传都只计一次。
- Excel 各行的指纹取业务主键（课程名 + 完成数 + 得分率、提问时间 + 提问内容等），
  重复导入整张表会被逐行忽略。
- 全流程**不调用大模型、不依赖网络**，打分只由词典与规则决定，因此结果可复算、可审计。

### 实测结果（基于贵校真实导出数据，5307 名学生、6.5 万条证据）

| 检验项 | 结果 |
| --- | --- |
| 4 张表全部重复导入一遍 | 新增 0 条，五维得分逐位不变 ✔ |
| 上传 1 份江南文化主题 Word 作业 | 五维全部上升，文化研创 +0.088 ✔ |
| 同一文件再传 3 次 | 得分纹丝不动 ✔ |
| 改文件名后再传 | 按内容去重，未重复计分 ✔ |
| 灌入 40 份不同作品 | 各维度 0.989~0.994，**未越过 1.0** ✔ |
| 问卷题目自动归类（推荐题本 20 题） | 20/20 全对 ✔ |
| 网页版与 Python 版算分一致性 | 250 个数值最大差异 0.000e+00 ✔ |
| 网页版与 Python 版排序依据一致性 | 40 名学生逐项一致，差异 0.000e+00 ✔ |

网页版在浏览器中另做了同样六项检验，结果一致；4 张表全部解析耗时不到 1 秒。

## 六、四张导出表的字段用法

| 导出表 | 用到的字段 | 主要支撑维度 |
| --- | --- | --- |
| 学生报名情况 | 学号、姓名、学院、专业、行政班级、报名课程 | 建索引；志趣、体验 |
| 学生视频完成率 | 课程（班级）、视频总数、已完成视频数、完成率 | 体验、认知 |
| 学生作业完成率 | 课程（班级）、需提交/已提交数、得分率 | 认知、研创、志趣 |
| 文化对话记录 | 学生昵称、账号、提问时间、用户提问、AI 回复、token | 认知、志趣、认同 |

对话表只有昵称与账号、没有学号，系统按 `昵称 → 学号` 反查关联；
实测 871 条对话中 816 条成功关联（约 94%），未关联的会在上传日志里报出数量。

## 七、已知限制

1. **视频作业**只读取时长、体积等元数据与文件名；若同目录存在同名 `.srt`/`.vtt`/`.txt`
   字幕或脚本文件，会一并纳入文本分析（建议要求学生随视频提交脚本，评分会准得多）。
2. **PDF 解析**依赖可选的 `pypdf`；未安装时 PDF 只按文件名与体积计量。
   桌面版为减小体积默认未打包 PDF 支持，需要的话把 `hlr_desktop.spec`
   的 `excludes` 里的 `'pypdf'` 去掉重新打包。
3. **问卷自动归类**在推荐题本上是 20/20，但若换成自拟题目准确率会波动——
   请在 `questionnaire_map.json` 里显式指定题干与维度的对应，这是最稳的做法。
4. 年级以**上传时选择的**为准；导出表里的"年级"字段过于杂乱
   （`大一`/`2025级`/`25`/`一年级`/`2025级硕士研究生` 等十余种写法），仅作兜底推断。

## 八、三种用法怎么选

| 场景 | 用哪个 | 理由 |
| --- | --- | --- |
